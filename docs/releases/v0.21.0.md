## Новое

- `agent-sync` ищет сессии Hermes **во всех домах на машине**: `%LOCALAPPDATA%\hermes`, `%USERPROFILE%\.hermes` (если там лежит `state.db`) и `<user>/.hermes` каждого **запущенного дистрибутива WSL** (`\\wsl.localhost\<distro>\...`, фолбэк `\\wsl$`). `doctor`/`status`, `search`, `--sessions`, MCP и синхронизация видят их одним каталогом.
- Одинаковый `id` сессии в двух домах — одна сессия (скопированный `state.db`): выигрывает первый дом в порядке `%LOCALAPPDATA%\hermes` → `%USERPROFILE%\.hermes` → WSL, в каталоге остаётся одна строка.
- Чтение WSL-домов идёт через локальную копию `state.db`: SQLite не умеет делить WAL по UNC, и прямое чтение живой базы через `\\wsl.localhost` падает с `database is locked`. Запись в удалённый дом (импорт, удаление через `--manage`) возвращается обратно только пока WAL не менялся; иначе операция отказывается и ничего не затирает.
- `HERMES_HOME` (в том числе в профилях `--profile`) как раньше означает ровно один дом — профили с раздельными копиями сессий не затронуты. Новый `AGENT_SYNC_HERMES_WSL=0` отключает обход WSL.

## Совместимость

- Без изменений формата хранилища: `ObjectKind.HermesSession` и пакеты сессий не менялись, старые сборки читают индекс как раньше. Обновлять все машины перед первым `push` не требуется.
- После обновления каталог и `search` включат сессии из WSL-домов — при первом `push` они добавятся в репозиторий как новые объекты.
- Импорты с других машин по-прежнему кладутся в первый дом; если на машине есть только WSL-дом — в него.
- Дистрибутивы WSL, которые в данный момент не запущены, не сканируются.

## Загрузка

- `agent-sync.exe` — автономная сборка Windows x64.
- `agent-sync-light.exe` — облегчённая сборка Windows x64, требующая .NET 10.
- Для обеих сборок опубликованы контрольные суммы SHA-256.

## Обновление

Закройте окна `--sessions` и `--manage`, затем выполните:

```powershell
agent-sync update
```
