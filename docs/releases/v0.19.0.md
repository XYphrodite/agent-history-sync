## Новое

- Седьмой агент: **Hermes Agent**. Синхронизируются сессии из `state.db`: один зашифрованный пакет на сессию (`he-<profile>~<session-id>`) со строкой `sessions` и её `messages`. `config.yaml`, ключи, логи, WAL и полнотекстовый индекс не читаются и не отправляются.
- Дом Hermes: `HERMES_HOME`, затем `%LOCALAPPDATA%\hermes`, затем `%USERPROFILE%\.hermes`, если там лежит `state.db`. Именованные профили берутся из `profiles\<name>\state.db`. В профилях `--sessions-dir` это каталог `hermes`.
- Локальный идентификатор строки SQLite в пакет не входит, поэтому один и тот же разговор получает один хеш на разных машинах. Пустые колонки тоже не входят в хеш.
- Активная сессия Hermes (процесс `hermes` и сообщение моложе 30 секунд) откладывается до следующего запуска. Каталог без `state.db` не считается удалением всех сессий.
- `--sessions`, `search` и MCP видят Hermes: панель агента, копирование между агентами, просмотр и поиск по тексту реплик.
- `status` печатает `hermes-home=`, `hermes-sessions=` и `hermes-uncertain=`. `doctor` добавляет проверку `hermes-paths`.

## Совместимость и ограничения

- **Обновите все машины, которые делят репозиторий, до первого `push` с сессией Hermes.** `ObjectKind.HermesSession` — новое число в зашифрованном индексе (12, следом за `MuseSession`). Старая сборка отвергнет весь индекс, и `pull` перестанет работать для всех агентов, а не только для Hermes. Обновлённая сборка печатает `hermes-sessions=` в `status`, старая — нет.
- Копия в Hermes записывается в `state.db` профиля `default` как сессия `source=cli` с текстом реплик пользователя и ассистента. Результаты инструментов и reasoning в переносимую копию не входят.

## Загрузка

- `agent-sync.exe` — автономная сборка Windows x64.
- `agent-sync-light.exe` — облегчённая сборка Windows x64, требующая .NET 10.
- Для обеих сборок опубликованы контрольные суммы SHA-256.

## Обновление

Закройте окна `--sessions` и `--manage`, затем выполните:

```powershell
agent-sync update
```
